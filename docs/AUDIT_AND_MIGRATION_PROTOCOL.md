## Часть A. Полный аудит текущего приложения

### A1. Карта модулей и связей

```
Главная
├── Расчет раскладки потолка → Проекты → Комнаты
│     → Редактор стен → Раскладка (сетка/панорама/напр./свет)
│     → Отделка комнаты (пол / стены / потолок-материалы)
│     → Расчет материалов комнаты
├── Расчет материалов → проекты/комнаты / полный расчет / share
├── Расчет отделки → проекты (модуль finish) → FinishRoom
├── Импорт проекта (.ccproj)
├── Поставщики / Импорт чека / Стоимость  (админ, long-press Настройки)
└── Настройки (тема)
```

**Общая БД / модели:** проект и комната хранят стены, смещение сетки, свет, направляющие, конфиг материалов, отделку пола.  
**Связка раскладка ↔ материалы:** `calculateRoomMaterials` читает стены + offset + lights + `ceilingGuides` + тип/ячейка; шаблон каркаса пишет тип в комнату/проект (`materialsOverride`).

### A3. Риски и несостыковки (приоритет)

#### P0 — процесс / репозиторий
1. ~~**`flutter_app/` не закоммичен.**~~ **Сделано:** порт в git, `master` = Flutter 3.0.0, Kivy на `legacy-kivy` / `v2.1.4`.
2. ~~Параллельно Kivy в корне~~ **Сделано:** корень очищен; формулы только в Flutter (`materials_calculator.dart`).

#### P1 — логика / продукт
3. **Два «числа плит»:** на экране раскладки — целые+резаные ячейки; в смете — закупка N. Пользователю неочевидно без подписи «закупка» vs «ячейки монтажа».
4. **Упаковка резов направляющих** — по сумме длин (как у плит). Реально обрезки L-образные/разной ориентации; оценка оптимистична, но лучше прежнего «1 кусок = 1 профиль».
5. **Шаблон каркаса перезаписывает все направляющие** — ожидаемо, но без undo; стоит предупреждать, если уже была ручная разметка.
6. **Тип потолка с шаблона** ставит `materialsOverride` на комнату и обновляет проект — удобно для одной комнаты; в многокомнатном проекте с разными типами нужна дисциплина override.
7. **Классика Грильято / Armstrong** на чертеже оба рисуют каркас 600-модуля; решётка папа/мама в смете есть, **на плане решётка не рисуется** (только несущий каркас) — ок для v1, но монтажнику решётки на схеме нет.

#### P2 — UX / удобство
8. Нет явного **онбординга** режимов раскладки (сетка vs панорама vs напр.).
9. **Отделка** (стены/проёмы/изометрия) и **потолок** связаны слабо по навигации — есть кнопки, но нет единого «статуса комнаты» (чертёж ✓ / каркас ✓ / материалы ✓).
10. **Исполнительная документация / PDF-штамп / акты** — в бэклоге, не реализовано.
11. **Фото плана / AR-обход** — бэклог, не реализовано.
12. На Windows джойстик/жесты ок; на телефоне нужно отдельно прогнать hit-targets кнопок 3600/1200/600.

#### P3 — техника
13. `layout_screen.dart` очень большой (~1600+ строк) — кандидат на разбиение (painter / guides / controls).
14. Live rebuild сетки при джойстике — throttling есть; на огромных комнатах стоит профилировать.
15. Kivy README parity table в `flutter_app/README.md` уже устарела (нет направляющих, пола, шаблонов каркаса).

### A4. Связность разделов — вердикт

| Связка | Статус |
|--------|--------|
| Стены → сетка / площадь / материалы | Связано |
| Offset сетки → свет / направляющие (world sync) | Связано |
| Направляющие → счётчики в AppBar + смета | Связано |
| Шаблон каркаса → тип потолка + ячейка → смета | Связано |
| Отделка пол ↔ потолочная раскладка | Одна комната, разные поля; ок |
| Материалы ↔ поставщики ↔ стоимость | Связано через каталог/алиасы |
| Раскладка ↔ полный расчет проекта | Через `aggregateProjectTotals` |

**Итог аудита:** ядро потолка (чертёж → раскладка → каркас → смета) **логично и связано**. Главный операционный риск — **незакоммиченный Flutter**. Продуктовые дыры — документация сдачи, захват геометрии, явная подпись «закупка vs монтажные ячейки».

## Часть B. Протокол: от сохранённой Kivy-версии до текущего Flutter

### B1. Исходная точка (Kivy)

**Стек:** Python 3 + Kivy/KivyMD, Buildozer (Android), SQLite.  
**Возможности на момент «сохранённой» линии master (ориентир май–авг 2026):**
- Проекты / комнаты, редактор стен (джойстик), раскладка 600×600, свет
- Расчет материалов Armstrong / Грильято / GL (формулы от площади и рядов)
- Share текста материалов, темы, видеофон
- Поставщики, импорт чека, стоимость, админ-пароль
- Экспорт/импорт проектов, фиксы Android APK / DB path

**Ограничения Kivy, из‑за которых ушли во Flutter:**
- Производительность и стабильность на Android (слои, stencil, видео, стартовые краши)
- Сложность UI/жестов (long-press, InteractiveViewer-уровень камеры)
- Дальнейшее развитие (пол, каркас на чертеже, упаковка материалов) удобнее на одном UI-стеке

### B2. Этап 1 — Порт каркаса на Flutter

**Каталог:** `flutter_app/` (Dart / Flutter, Windows + Android target).

Перенесено / воссоздано:
- Меню: раскладка / материалы / отделка / импорт / поставщики / настройки
- `AppScope`, SQLite (`app_database`, `project_repository`, `supplier_repository`)
- Domain: `materials_calculator`, `ceiling_grid`, `models`, cost, catalog, aliases, receipt
- Экраны parity: projects, rooms, room editor, layout, materials, suppliers, cost, settings
- Тема, фон, админ long-press
- Тесты smoke + domain + repository

Документ parity: `flutter_app/README.md` (частично устарел относительно текущего функционала).

### B3. Этап 2 — Раскладка потолка: камера, сетка, свет

- Режимы: **Сетка / Панорама / Свет / Напр.**
- InteractiveViewer: pan/zoom; джойстик только двигает **offset сетки**, не камеру
- Синхронный center при входе, анти-мигание старой раскладки
- Свет: привязка к world-позиции при сдвиге/wrap сетки
- Live rebuild сетки при джойстике (throttle)
- Размеры плит / стен — переключатели

### B4. Этап 3 — Направляющие (каркас на чертеже)

Эволюция модели:
1. Маркировка линий сетки (`h:i` / `v:j`) + тип профиля  
2. Snap «не к стене» → баг: нельзя поставить от стены при полной плитке → **исправлено** на nearest grid line  
3. Отрисовка **кусков профиля** wall-to-wall с фазой якоря (не сплошная стена–стена без колпачков)  
4. Якорь `anchorAlongIndex` + миграция legacy без якоря к центроиду  
5. Параллельный сдвиг сетки: линия и якорь через `guideLineWorldCoord`  
6. Панорама пальцами в режиме «Напр.» (сетка — только джойстик)  
7. Шаблон каркаса: Армстронг / Грильято / GL + ячейка; диалог только по кнопке  
8. 3600↔2400: swipe без long-press delay; запоминание main kind при выборе 1200/600  
9. Счёт закупки: упаковка обрезков профилей (как у плит)

Цвета кнопок = цвета линий на чертеже.

### B5. Этап 4 — Формулы материалов (выравнивание со спекой)

Источник: `materials_spec_extracted.txt` (из Word «Калькулятор материлалов.docx»).

| Тема | Было | Стало |
|------|------|-------|
| Плиты/кассеты | full+cut / ceil(L/0.6)×ceil(W/0.6) | max(ceil(S/0.36), упаковка резов) |
| Папа/Мама | (S/0.34)×k | **N×k** (5/7/11) |
| GL заглушки | через площадь | **N×4** |
| Классика подвесы | ×4 | **×3** от 2400 |
| Каркас классика | шаг 600 для мелких ячеек | **как Armstrong**, несущие 2400 |
| Направляющие в смете | формулы или сырые куски | чертеж + упаковка scrap |

Связка: шаблон каркаса → `materialsCeiling` / `materialsCell` → смета.

### B6. Этап 5 — Отделка (пол / стены)

- Модуль finish: площади, проёмы, слои стен  
- Пол: ламинат/плитка, паттерны, смещение, поворот **+90°** (360° убран по запросу)  
- Размеры подрезанных досок/плиток на плане  
- Навигация из раскладки: «Отделка» / «Материал»

### B7. Этап 6 — UX-полировка (недавние сессии)

- Джойстик в редакторе снова на фоне плоскости (без залитой «полки»)  
- Snap направляющей к стене при полной плитке от края  
- Цветовая легенда 3600/1200/600/2400  
- Исправление сброса 2400→3600 при выборе 1200  

### B8. Что сознательно отложено (бэклог)

Файл правил: `.cursor/rules/product-backlog.mdc`

- Исполнительная схема PDF/PNG, акты, чеклист скрытых работ, сертификаты  
- Слои / проект vs факт / облако+роли / офлайн-first  
- Фото плана → полигон; RoomPlan / ARCore обход комнаты
